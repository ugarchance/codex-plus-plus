# Astra / macOS 26.901 compatibility validation (2026-09-08 → 2026-09-09)

Counterpart of [astra-windows-26.901.md](astra-windows-26.901.md). Source: `/Applications/ChatGPT.app` 26.901.51231 (8109), read-only throughout. Source ASAR SHA-256 `64fc2f27d2dddfa968acfacbe5e4e0328071bdc406351ff4a7d18f0b4692c83d`, source ASAR header SHA-256 `e2ab6e5985856e148ff78e79658e1241e9ab258d82453d201326bdd2e6779717`. Previously installed Codex++: 26.825.51511 (7377).

1. Anchor audit first, no code changes: `node tools/check-patches.mjs` against the 26.901 ASAR applies all 20 patches with unique matches in 7 JS files. The Windows Astra port (semantic anchors, `app-initial` / `app-primary` split, `settings-page` chunk) holds on macOS without modification. `patch/apply.mjs --check-only` now accepts the build after the hash was recorded.
2. First live launch of the patched copy aborted before bootstrap: `Failed to get integrity for validatable asar archive`. Measurement: the 26.901 Electron build has the `EnableEmbeddedAsarIntegrityValidation` fuse on, and `Info.plist` carries `ElectronAsarIntegrity` (SHA-256 of the ASAR header). The old installer removed that key with `plutil -remove`, which earlier builds tolerated and this build treats as fatal. Fix: `patch/mac-integrity.mjs` (counterpart of `windows-integrity.mjs`) rewrites only the `Resources/app.asar` hash in the copied plist after packing; the installer keeps the key. Header hash of the patched ASAR: `ff9b9e079490bbf4e462ebcf1578fcae158ec2b272c8de1ad5c492c7fbc96680`, verified against the installed plist. `tools/test-mac-integrity.mjs` covers plan cases, the plist round trip, idempotence, legacy plists without the key and mismatched-source rejection.
3. Saving a provider key on macOS failed the same way it first did on Windows: the Codex Electron build has no `safeStorage` binding on macOS either. `install/mac/keychain.c` (`codexpp-keychain`, compiled and ad-hoc signed by the installer next to `Codex++-bin`) keeps a random 256-bit master key in the login keychain (service `CodexPP Safe Storage`, add-only, secret through stdin/stdout only). `hub/provider-secrets.cjs` gains a darwin branch: AES-256-GCM per secret, `CXP-MACKC-1:` prefix, fresh IV per encryption, keychain read once per process. `tools/test-mac-keychain.mjs` builds the helper, uses a throwaway service name, and checks add-only behaviour, the round trip, tamper and foreign-format rejection, and master-key recovery after a cache reset.
4. Installer changes: `npm ci` on every run (the Windows port's `resedit` dependency was missing from a stale `node_modules`), keychain helper compile + sign, integrity rewrite after patching, and a `hub` subcommand that re-copies `hub/` and re-seals the bundle without a full reinstall.
5. Fresh install on 2026-09-09 with `ALLOW_UNTESTED_SOURCE=1 install/mac/install.sh install` (the hash was recorded afterwards): 20 patches applied, 7 files `syntax ok`, `macOS ASAR integrity: updated`, `Codex++-bin`, `codexpp-keychain` and the bundle signed, `codesign --verify --strict` passes. Bundle size 1.3 GB.

Known limit: the keychain item's access list names the helper binary. If a later install produces a different `codexpp-keychain` binary, macOS may ask once whether it may read the item; choose Always Allow. Until then `Settings → Providers` reports that keychain access failed and the key must be entered again.
